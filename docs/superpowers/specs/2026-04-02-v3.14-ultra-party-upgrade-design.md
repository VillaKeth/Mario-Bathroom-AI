- Inserted between Phase 2 (silence) and Phase 3 (toast)
- Mario counts "TEN-a! NINE-a! EIGHT-a!..." with building intensity
- SFX: escalating drum hits or heartbeat sound per number
- TTS pre-cached at server startup for each number to guarantee zero latency
- Visual: large countdown number overlay on screen

- Change `pygame.mixer.music.play(loops=1)` → `loops=0` (single play)

- Calculate exact duration from file metadata, not hardcoded

### Recovery
- After music finishes, Mario delivers warm closing line (e.g., "Lisa would've loved this party...")
- 5-second pause, then smooth transition back to party mode
- Clear all memorial flags, resume idle cycle

### Idle Suppression Fix
- Ensure idle text queue is flushed when memorial starts (not just suppressed)
- No leftover idle bubbles should appear during or after memorial

## Sub-Project C: Person Detection & Identification

### Architecture
Three identification layers running concurrently on RTX 3090 Ti:

1. **Real-time face detection** (continuous)
   - YOLO v8 on webcam feed → face_recognition for encoding
   - Mario greets by name when recognized face enters frame
   - New face triggers "Who are you?" interaction

2. **Voice identification** (per-utterance)
   - Resemblyzer 256-dim voice embeddings
   - Match voice to known guests during conversation
   - Supplements face ID when face not visible

3. **Periodic presence scan** (every 30 seconds)
   - Count unique faces in frame → guest energy tracking
   - Feed guest count into night progression system

### Dynamic Learning Flow
1. New face detected → Mario asks "Hey! I don't-a recognize you! What's your name?"
2. Guest responds → name extracted from speech via LLM
3. Face encoding + voice embedding + name stored in Qdrant
4. If guest doesn't respond or name extraction fails after 2 attempts, assign "Mystery Guest #N" and retry next encounter
5. Next encounter → "Hey [Name]! Good to see you again!"

### Jacob VIP Pre-Registration
- Face photo sourced from LinkedIn profile (contactout.com link)
- Pre-loaded face encoding + voice embedding (if available)
- All VIP knowledge from `server/vip_knowledge.py` linked to identity
- Always recognized immediately — never asks "who are you?" to Jacob

### Storage — Qdrant Collection Architecture
- `mario_memories` (existing): 384-dim vectors (fastembed MiniLM-L6-v2) — semantic conversation memories
- `mario_faces` (new): 128-dim vectors (face_recognition dlib) — face encodings per guest
- `mario_voices` (new): 256-dim vectors (Resemblyzer) — voice embeddings per guest
- Each collection is independent with its own dimension. Guest linkage via shared `guest_name` payload field.
- Persistent across server restarts via Qdrant on-disk storage

## Sub-Project D: Sentiment & Mood Overhaul

### LLM-Analyzed Sentiment
- Each LLM call includes sentiment analysis instruction in system prompt
- LLM returns structured response: `{ "reply": "...", "emotion": "excited", "energy": 0.8 }`
- Zero extra latency — sentiment extracted alongside reply generation
- Replaces keyword-based emotion detection in `server/emotions.py`

### Emotion → Pose Mapping
- **Server emotions** (13 in `server/emotions.py`): happy, excited, bored, surprised, confused, worried, loving, mischievous, sleepy, proud, frustrated, embarrassed, neutral
- **Client sprite map** (26 in `client/mario_display.py`): happy, excited, surprised, confused, annoyed, sleepy, mischievous, laughing, sad, angry, nervous, scared, love, loving, proud, embarrassed, disgusted, determined, bored, worried, curious, thinking, shocked, idea, frustrated, neutral
- **LLM emotion tag set**: All 26 client emotions are valid tags. LLM can emit any of them.
- Server `Emotion` class expanded from 13 → 26 to match client sprite map
- Selection now driven by LLM tag instead of keyword matching
- Fallback to keyword matching if LLM doesn't return emotion tag

### Conversation Energy Tracking
- Running average of energy scores per-guest
- High energy → more animated poses, louder TTS, faster idle cycles
- Low energy → calmer poses, softer tone
- Feed energy data into night progression phase transitions

### Mood Persistence
- Store mood shifts per-guest in Qdrant
- Example: "Jacob was laughing about Deltarune at 10:30 PM"
- Mario can reference past moods: "You were cracking up earlier about Lancer!"

## Shot Events System (New)

### Architecture
Generalized event system replacing the single-purpose memorial:

```python
class ShotEvent:
    name: str           # "lisa_webb_memorial", "birthday_boy", "deltarune"
    tone: str           # "solemn", "celebratory", "fun"
    trigger_type: str   # "auto", "voice", "admin"
    voice_keywords: list[str]
    countdown: bool     # 10-sec dramatic countdown
    music_file: str     # optional honor track
    music_duration: int # seconds
    recovery_line: str  # what Mario says to return to party
    fired: bool         # prevent double-firing
```

### Configured Events

#### 1. Lisa Webb Memorial (solemn)
- **Trigger**: Auto at 45-90 min OR voice ("Lisa", "Aunt Lisa", "Lisa Webb")
- **Phases**: Announcement → Silence → Countdown → Toast → Music → Recovery
- **Music**: `lisa_memorial.mp3` (~2 min, single play)
- **Recovery**: "Lisa would've loved this party... Now let's-a keep celebrating!"
- **Skip**: `Ctrl+Shift+L`

#### 2. Birthday Boy Shot (celebratory)
- **Trigger**: Voice ("birthday shot", "shot for Jacob") OR admin API
- **Phases**: Announcement → Countdown → Toast → Recovery
- **Mario says**: "It's-a time to take a shot for the BIRTHDAY BOY! Jacob Hoppenstedt, this one's for YOU!"
- **No silence phase** (it's celebratory)
- **Recovery**: "WAHOO! Now THAT'S how we party!"

#### 3. Deltarune Shot (fun)
- **Trigger**: Voice ("deltarune shot", "shot for deltarune") OR admin API
- **Phases**: Announcement → Countdown → Toast → Recovery
- **Mario says**: "This shot goes out to the heroes of the Dark World! Kris! Susie! Ralsei! And the one and only LANCER! Jacob voiced Lancer, and Keth voiced Susie! To Deltarune!"
- **Recovery**: "Haha! What a fun-a game! Now back to the party!"

### Shot Event API
- `POST /admin/trigger_event/{event_name}` — trigger any event by name
  - Request: `{}` (no body required)
  - Response: `{"status": "triggered", "event": "lisa_webb_memorial"}` or `{"status": "already_fired", "event": "..."}`
- `GET /admin/events` — list all events and their status
  - Response: `{"events": [{"name": "lisa_webb_memorial", "fired": false, "tone": "solemn"}, ...]}`
- `POST /admin/reset_event/{event_name}` — re-enable a fired event
- Events are one-shot by default (can be re-enabled via admin)

### Architecture Note
The Shot Events System is built FIRST as a generalized framework. The existing memorial code in `server/main.py` (`_run_memorial()`) is then refactored to become the first ShotEvent config (lisa_webb_memorial). Sub-Project A implements the memorial-specific enhancements (voice trigger, countdown, etc.) as features of this framework.

## Easter Egg: "The N-Word Incident"

### Behavior
- Mario randomly says: "Jacob Hoppenstedt said the N-Word earlier at this party... Oops! I shouldn't have-a said that!"
- Fires 3-5 times throughout the night, any party phase
- Random intervals with minimum 30-minute gap between occurrences
- Tracked counter ensures it stays within 3-5 range
- Delivered as a regular idle line with "mischievous" or "embarrassed" emotion
- TTS pre-cached for consistency

### Implementation
- Add to idle behavior pool with special scheduling logic
- **Scheduling algorithm**: At party start, pre-compute 3-5 firing times by randomly selecting from 30-min slots across the 8-hour party window. Store in server state.
- Not a "shot event" — just a recurring joke line
- Counter persisted in server state, reset on fresh party start
